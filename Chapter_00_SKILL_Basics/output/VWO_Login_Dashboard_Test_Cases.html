1. Summary and conventions

This specification turns the supplied PRD into executable manual test cases. It includes the skill’s detailed test-case fields and a compact execution summary. Requirements are identified by descriptive trace labels mapped to PRD statements below; the labels are not external requirement IDs.

Trace labelPRD requirement coverage
AUTH-01–04Email/password authentication; field validation on blur; actionable failures; loading feedback; successful dashboard handoff.
PASS-01–03Forgot password, email recovery, secure reset token, and enforced password requirements.
SESS-01–03Remember Me, secure session handling, configurable timeout, secure token management.
AUTHX-01–03Optional MFA; enterprise SSO (SAML/OAuth); optional Google/Microsoft social login.
UX-01–04Responsive/touch-friendly UI, autofocus, clickable labels, loading states, branding, Light/Dark Mode, announcements, registration route.
A11Y-01–03Screen-reader support, ARIA labels, keyboard navigation, high contrast, WCAG 2.1 AA.
SEC-01–05HTTPS, protected authentication data, secure password/session handling, rate limiting, privacy/enterprise audit expectations.
PERF-01–03Login page under 2 seconds on standard connections, asset optimization/CDN, availability and concurrent login scale.
INT-01–04Core platform transition, analytics, customer support, registration/onboarding, recent activity.
Specification gap handling: Do not infer exact password rules, error wording, lockout thresholds, session duration, reset-token expiry, supported browser versions, concurrency levels, or recovery alternatives. Verify them against approved product/security configuration. Cases depending on an undefined value are marked “per approved policy” and should not be signed off until that policy is supplied.

Priority: P0 = critical authentication/security path; P1 = high priority; P2 = normal/conditional. Type: Functional, Validation, Security, UX, Accessibility, Performance, or Integration. Execution result: Not Run until tester records Pass/Fail/Blocked.

Test data: Use only approved non-production accounts and provider tenants. References below are placeholders, not credentials. Never record actual passwords, reset tokens, or session tokens in results.
